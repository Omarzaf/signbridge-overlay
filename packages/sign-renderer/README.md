# sign-renderer

The visible layer. It takes a `PlaybackState` resolved by `packages/sync-engine`
and turns it into something on screen — reviewed signing media when a segment is
approved and ready, an explicit caption fallback in every other case.

Dependency-free. It imports types from `packages/sync-engine` by relative path
and nothing else, which `tools/verify-baseline.mjs` enforces for the whole
playback path.

## What each module is responsible for

| Module | Responsibility |
| --- | --- |
| `presentation.ts` | Maps every playback state to readable text. There is no input that produces an empty screen. |
| `geometry.ts` | Sizes and places the signing surface. Can only letterbox; cannot crop or mirror. |
| `timeline.ts` | Moves the surface to match one media-clock sample. Runs no clock of its own. |
| `signSurface.ts` | Binds the three to a DOM element. |

## The two rules this package exists to keep

**It never crops and never mirrors.** `docs/linguistic-safety.md` prohibits
cropping or mirroring hands, face, torso, or required nonmanual grammar. These
are not presentation preferences: a mirrored sign can be a different sign, and a
crop can remove the grammar carrying the meaning. `resolveAssetGeometry` scales
by `min(...)` — the `max(...)` variant is the "cover" strategy, and cover is a
crop — and `SIGN_SURFACE_STYLE` pins `object-fit: contain` and `transform: none`
as the only style the surface may carry. `geometry.test.ts` asserts this across
a grid of container and asset aspect ratios, and asserts that its own overflow
check catches the cover geometry, so the guard is known to be able to fail.

**It never invents motion.** Any state other than `active_sign` pauses the
surface and hands the moment to captions. Motion on the signing layer while no
approved segment covers that moment is motion a viewer could reasonably read as
signing, which is the one failure this project cannot afford.

## What it is not

It does not decide what to show. That is `packages/sync-engine`'s job, and the
split is deliberate: the renderer cannot promote an unapproved segment, because
it has no path to the manifest at all.

It has no notion of a signed language. It renders whatever asset the sync engine
resolved. The declaration of language, region, and dialect lives in the SignPack
and is the reviewer's, not the renderer's.

## Status

No reviewed signing media exists in this repository, so the `active_sign` path
has never rendered real content. The synthetic motion generated by
`tools/generate-synthetic-motion.mjs` is abstract geometry used to exercise
synchronisation, seeking, and the fallback states. It is not a signed language
and is never presented as one.
